# Developing Kanso

Kanso is a Tauri v2 desktop app: a React + TypeScript + Tailwind interface in a WebView2
window, and a Rust backend. Everything that can be decided without a window lives in a pure
Rust crate, `kanso-core`, which builds and is unit-tested on any system.

## Building

You need [Node.js](https://nodejs.org) 22 and a stable [Rust](https://rustup.rs) toolchain.
The desktop app itself builds on Windows 10/11 (WebView2 is part of Windows 11; on Windows 10
the installer fetches it).

```bash
npm install
```

```bash
npx tauri dev
```

```bash
npx tauri build
```

The installers land in `src-tauri/target/release/bundle/` (`nsis/*.exe` and `msi/*.msi`).

`npm run dev` alone opens a **browser preview** backed by a small sample library: no scan, no
launch, no backend. It runs on any system and is the quick way to work on the interface. A
page can put its own games in `window.__KANSO_PREVIEW_GAMES__` before the app loads.

Set `KANSO_STEAM_ROOT` to a folder containing `steamapps/` to scan it instead of the Steam
installation found in the registry. This also works on Linux and macOS, where it is the only
way to exercise the real scan from end to end:

```bash
KANSO_STEAM_ROOT=/path/to/fake/Steam npx tauri dev
```

## Checks

What CI runs, and what to run before a pull request:

```bash
npm run build
```

```bash
npm run test:rust
```

```bash
cargo clippy -p kanso-core --all-targets --manifest-path src-tauri/Cargo.toml
```

`npm run build` type-checks the interface (the four dictionaries in `src/i18n/` must have the
same keys, or it does not compile). `npm run test:rust` runs the tests of `kanso-core`: the
scanners on recorded or constructed files, the theme validator on the example themes of the
guide, every official plugin in the real sandbox against canned answers of its service, and
the examples printed in `docs/PLUGINS.md` and `docs/THEMES.md`, so the guides cannot drift
from the code.

What no automated test covers is in [MANUAL-TESTS.md](MANUAL-TESTS.md).

## Layout

- **`src/`** — the interface.
  - `App.tsx` holds the state; `components/` the pages (library, Home, Store, News,
    statistics, emulators), the game's sheet and the settings.
  - `lib/backend.ts` is the only door to the backend: every command is called from there, and
    the same functions answer with sample data in the browser preview.
  - `lib/themes.ts` applies a theme as CSS variables and data attributes on the root element;
    `index.css` reads them. A theme never carries CSS of its own.
  - `i18n/` has one dictionary per language (Italian, English, Spanish, Russian).
  - `fonts.css` is generated by `scripts/generate-fonts-css.mjs` from the bundled fonts.
- **`src-tauri/crates/kanso-core/`** — the core, with no GUI dependency.
  - `scanner/` — one module per store (Steam, Epic Games, GOG, Ubisoft Connect, EA app,
    Battle.net, Xbox app) plus custom folders. Registry-based scanners receive entries
    already read, so their logic is tested on mocked data. A game reported by several stores
    is listed once. `epic_catalog.rs`, `gog_galaxy.rs`, `ubisoft_cache.rs`,
    `steam_packages.rs` and `steam_licenses.rs` read what the clients keep on disk about the
    account's games (and, for Steam, whose each one is), with no sign-in.
  - `emulators/` — recognising emulators, reading their own settings for the games folders,
    building the command line that starts a game.
  - `metadata.rs`, `owned.rs` — covers, descriptions, genres and tags (SteamGridDB and the
    Steam store), and the games that are owned but not installed.
  - `store.rs`, `db.rs` — the library: merge rules and the SQLite database (`library.db` in
    the app's local data folder), the single source of truth for games, metadata, favourites,
    play history and manual edits. `config.json` holds the settings, `covers/` the cover art.
  - `*_account.rs`, `accounts.rs`, `signin.rs`, `secrets.rs` — optional sign-in to the
    stores; see [ACCOUNTS.md](ACCOUNTS.md) for what is kept and where.
  - `theme.rs` — the theme format and its validator; see [THEMES.md](THEMES.md).
  - `plugins/` — manifest validation, the QuickJS sandbox, the request gate, the validated
    output, caching; see [PLUGINS.md](PLUGINS.md).
  - `deals.rs`, `news.rs`, `gamepass.rs`, `weather.rs`, `dlss.rs`, `playtime.rs`,
    `achievements.rs` — what their names say.
- **`src-tauri/src/`** — the desktop shell: the IPC commands, the tray icon, the sign-in
  window, the threads that measure play time and run plugins in the background. Games are
  started by their id in the database; an address or a path never comes from the interface.
- **`plugins/`** — the official plugins, compiled into the app and run by the tests.
- **`docs/`** — the guides, and the example themes in `docs/themes/`.
- **`.github/workflows/`** — `build-windows.yml` (tests on Linux, then tests and installers
  on Windows, on every push and pull request) and `release.yml` (a draft release with the
  installers attached).

## Rules the code keeps

These are checked by tests where a test can check them; a change that breaks one needs a very
good reason.

- **No secrets in the repository.** No `.env` files, no API keys. The user's keys live in the
  local `config.json` only.
- **No server, no telemetry.** Kanso talks to the stores' and services' own public addresses,
  from the user's PC, and to nothing of ours.
- **A password never passes through Kanso.** Signing in happens on the store's own page.
- **A theme is data.** Every value is a colour, a number, or a name from a closed list. No
  free CSS, no scripts, no paths, no remote resources.
- **A plugin is a guest.** It runs in a sandbox with no files and no network but the hosts it
  declares; it returns data and Kanso draws it. An official plugin that contacts a site other
  than Steam, adds a part to Home or brings a library is off until the user switches it on.
- **The user's choices win.** Accessibility settings apply on top of any theme; a theme can
  rearrange everything but cannot lock the user out of their games.
- **Four languages.** Every text of the interface exists in Italian, English, Spanish and
  Russian.

## Releasing

1. Set the new version in `package.json`, `src-tauri/Cargo.toml`,
   `src-tauri/crates/kanso-core/Cargo.toml` and `src-tauri/tauri.conf.json`, and add its
   section to `CHANGELOG.md`.
2. Once that is on `main`, run the **Release** workflow from the Actions tab (or push the tag
   `v<version>`). It runs the tests, builds the installers and creates a **draft** release
   with them attached, together with their SHA-256 sums.
3. Read the draft, try the installer, press *Publish*.
